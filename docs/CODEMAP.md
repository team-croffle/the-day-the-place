# 코드맵 — 파일 구조 · 역할 · 연관성

코드를 읽기 전에 먼저 보는 지도다. 어떤 파일이 있고, 각자 무슨 일을 하고, 서로 어떻게 물려 있는지를 적는다.
규칙·워크플로는 [`AGENTS.md`](../AGENTS.md), 제품 계획은 로컬 [`.ai/ROADMAP.md`](../.ai/ROADMAP.md)를 본다.
구조가 바뀌면 같은 작업 단위에서 이 파일을 고친다(AGENTS.md「코드맵」 참고).

## 한눈에 보기

네 덩어리다. `shared`가 가운데에서 타입과 상수를 대고, `server`와 `web`이 그것을 같이 쓴다.

운영에서는 `dayplace.croffledev.kr`의 Cloudflare Worker가 화면을 제공한다.
`/api`와 `/api/*`는 `worker/index.mjs`가 홈랩의 `https://api.dayplace.croffledev.kr`로
경로를 유지해 전달한다. 나머지는 `ASSETS` 바인딩으로 정적 파일과 SPA 폴백을 제공한다.

```
사용자 ─→ web (Vue 3 + Vite, :5173)
             │  fetch /api/...   (개발 중에는 vite proxy → :3000)
             ▼
          server (NestJS, :3000, 전역 프리픽스 /api)
             │                         ▲
             ├─→ TourAPI (장소·좌표, 24시간 메모리 캐시)
             └─→ Postgres (users, exhibitions, favorites, 수집 커서)
                                       │
          collector (Python 배치) ── JSON ──► server 가 exhibitions에 넣고 종료분을 지운다
                shared (타입·상수. 빌드하지 않고 소스를 직접 참조)
```

| 영역      | 패키지 이름              | 위치         | 한 줄                                             |
| --------- | ------------------------ | ------------ | ------------------------------------------------- |
| 프런트    | `@nest-vue/web`          | `web/`       | Vue 3 + Vite. 지도 화면이 v0.1의 본체             |
| 백엔드    | `@nest-vue/server`       | `server/`    | NestJS. TourAPI를 대신 호출해 정규화              |
| 공용 계약 | `@nest-vue/shared`       | `shared/`    | 타입·상수. 빌드 산출물이 없다                     |
| 배치      | (pnpm 워크스페이스 아님) | `collector/` | Python + uv. 특별전을 모아 `exhibitions`에 넣는다 |

## shared — 계약이 모여 있는 곳

`shared/src/index.ts`가 열한 파일을 `export *`로 묶는다. 서버와 웹이 같은 모양을 쓰게 하는 유일한 지점이다.
빌드하지 않는다. 서버는 tsconfig `paths` + `tsc-alias`로, 웹은 vite alias로 **소스를 직접** 가리킨다.

## collector — 협회 글 배치

구현은 `collector/`에 있다. `run()`이 한국박물관협회 회원관 소식과 뮤지엄뉴스 전시를 읽고, 추출한 전시만 서버 ingest로 보낸다. DB에 직접 붙지 않는다. 파일 구성은 `collector/README.md`가 정본이다.

DB에 남는 수집 결과는 추출된 전시 행과 출처별 마지막 글 번호다. 글 원문, HTML, 전시정보(통합) 응답, 소장품 목록은 넣지 않는다. 옛 연합뉴스 코드는 `archive/yonhap-collector`에 있다.

서버 `server/src/collector/`의 ingest API는 그대로다. 수집기도 그 경로로 보낸다.

## 핵심 흐름 1 — 지도 핀이 화면에 찍히기까지

1. `routes/map.vue`가 뜨면서 서울 중심으로 지도를 바로 만들고, `useMapPlaces().fetchAll()`과 `resolveMapCenter()`를 동시에 돌린다. 위치가 오면 중심만 옮긴다. 카카오 `Map`은 칸 너비·높이가 0보다 클 때 만든다.
2. `fetchAll`은 전국 bbox로 `GET /api/places/map?swLat=33&swLng=124.5&neLat=38.9&neLng=132` 한 번만 던진다.
   (서버 상한이 8도라 이 값이 그 안에 들어간다. 지도를 움직여도 다시 부르지 않는다.)
3. 서버: `ValidationPipe` → `MapPlacesQueryDto`(+`map-bbox.ts`) → `PlacesController.listMap` → `PlacesService`
   → `fetchMapPlaces(query, 어댑터콜백)`.
4. `TourAdapter.listByBbox`가 캐시를 본다. 24시간 안이면 그대로 주고, 같은 키가 이미 날아가 있으면 그 약속에 합류한다.
5. `tour.client.ts`가 화면 크기를 보고 갈래를 고른다. 좁으면 반경 조회, 넓으면 지역코드(옛 cat) 조회에 더해 `lclsSystm` 전국 조회를 붙인다. 부분 실패는 살린다.
6. `tour.mapper.ts`가 한 줄씩 `PlaceSummary`로 바꾸고(카테고리·좌표 없는 것 버림), bbox로 한 번 더 걸러 중복을 없앤다.
7. 응답은 `{ data: { tour: { ok, items }, heritage: { ok:false, error:'not_requested' } } }`.
   웹은 `tour.ok`만 보고 `places`에 넣는다.
8. `map.vue`가 종류·지역·검색으로 `filteredPlaces`를 만든다. 검색어는 180ms 뒤에 반영한다. 사이드바 건수는 그 전체(지역 칩 기준)고, 카드 DOM은 보이는 줄만 만든다. 고른 장소가 없으면 그 목록을 `PlaceMarkers`에 주고, 고르면 그 핀만 남기고 우측 `MapPreview`가 너비 애니메이션으로 열린다. 핀 클릭은 줌·중심을 바꾸지 않는다. 목록에서 화면 밖 장소를 고르면 그때만 중심으로 옮긴다. 검색만 하고 아직 안 고르면 핀은 없다. 지도를 끌면 화면 안 핀만 다시 그리고, 줌 애니메이션 동안에는 타일 배율을 읽어 같은 비율로 옮긴다. 레벨 12 이상이면(선택이 없을 때) 핀만 숨긴다. 핀 클릭은 카카오 `click` 좌표를 캔버스 핀에 맞춰 본다.

## 핵심 흐름 2 — 응답 봉투와 에러

- 성공은 어디서나 `{ data }`(`ApiResponse<T>`). 목록은 `Paginated<T>`.
- 실패는 `http-exception.filter.ts`가 `{ statusCode, message, error, path, timestamp }`로 만든다.
- 웹의 `apiFetch`가 그 모양을 그대로 읽어 `ApiError`로 던진다. 양쪽이 `shared/src/types/api.ts` 하나를 본다.
- 외부 API 실패는 예외로 터뜨리지 않고 `PlaceSourceResult`의 `{ ok:false, error }`로 내려보낸다.
  "여기 장소가 없음"과 "호출이 깨짐"을 화면이 구분할 수 있게 하려는 것이다.

## 짝을 맞춰 둬야 하는 곳

운영 웹은 Cloudflare Workers `dayplace`이고 주소는 `https://dayplace.croffledev.kr`이다.
`VITE_API_BASE_URL`은 `/api`다. Worker가 그 경로를 `https://api.dayplace.croffledev.kr`로 넘긴다.
서버 `CORS_ORIGIN`은 웹 오리진, `BETTER_AUTH_URL`은 API 호스트다. GHCR 이미지 이름은
`ghcr.io/team-croffle/dayplace`이고, 릴리즈 워크플로와 compose가 같은 이름을 쓴다.

| 한쪽                             | 다른쪽                                                                | 무엇이 깨지나                                  |
| -------------------------------- | --------------------------------------------------------------------- | ---------------------------------------------- |
| `shared`의 `API_PREFIX`('api')   | `web/vite.config.ts`의 `/api` 프록시, Docker 헬스체크                 | 경로가 어긋나 404                              |
| `shared`의 `API_ROUTES`          | 서버 컨트롤러 경로, `useMapPlaces`의 URL                              | 같은 문자열이 두 곳에서 갈라진다               |
| `shared`의 `USER_ROLES`          | `schema/users.ts`의 `user_role` enum, Better Auth `role` 추가 필드    | DB enum과 세션 역할이 갈라진다                 |
| `BETTER_AUTH_URL`                | 인증 메일 링크                                                        | 비우면 `localhost:3000` 링크가 나간다          |
| `CORS_ORIGIN`이 `https://`       | 세션 쿠키 `Secure`. 값은 `https://dayplace.croffledev.kr`             | 웹 오리진과 다르면 로그인이 안 남는다          |
| `shared`의 `EXHIBITION_STATUSES` | `schema/exhibitions.ts`의 `exhibition_status` enum                    | 수집기 상태와 DB enum이 갈라진다               |

| `release.yml`의 `IMAGE_NAME`     | `docker/docker-compose.yaml`의 이미지 `ghcr.io/team-croffle/dayplace` | 서버가 다른 이름의 이미지를 받는다             |

## 지금 비어 있는 곳 · 함정

- 수집기는 협회 회원관 소식과 뮤지엄뉴스 전시를 읽고, 추출된 전시 행과 출처별 글 번호만 DB에 남긴다. 글 원문, HTML, 전시정보(통합) 응답, 소장품 목록은 넣지 않는다. 기간은 규칙으로 읽고, 종료일을 못 읽은 글만 Gemini에 보낸다. 이미지 파일은 복사하지 않는다. 소장품은 `GET /api/places/tour/:id/relics`와 `GET /api/places/relics`로 읽고 DB에 넣지 않는다. 옛 연합뉴스 코드는 `archive/yonhap-collector`에 있다.
- `heritage`(국가유산 API) 갈래는 자리만 있다. 항상 `not_requested`로 내려간다.
- `HealthCard.vue`, `useApi()`(컴포저블 쪽)는 화면에 붙어 있지 않다. 지도는 `apiFetch`만 쓴다.
- 마커 클릭 인포윈도우와 우측 미리보기는 장소 선택 시에만 열린다. 둘 다 상세로 간다. 평점·시대·키워드는 데이터에 없어서 넣지 않았다.
- 시안의 평점·시대·키워드는 데이터에 없어서 사이드바에 넣지 않았다.
- 메인 아래 추천 유적지와 시대 구분은 자리만이다. 박물관·유적지·특별전 목록은 데이터를 보여 준다. 메인 검색은 이름과 지역을 지도로 넘긴다.
- `server/README.md`에 적힌 `HERITAGE_API_*`, `NODE_ENV`는 코드가 읽지 않는다.
- 서버 산출물 경로가 `dist/server/src/main.js`다(`rootDir`가 저장소 루트라서). 실행 스크립트가 이 경로를 쓴다.
- 가입은 `email_verified` 전에는 세션을 주지 않는다. Resend 도메인 인증 전에는 시험 계정 메일로만 발송된다. 첫 관리자는 DB에서 `role`을 `admin`으로 바꾼다.
- `/admin`은 회원과 수집 숫자를 본다. `GET /api/collector/cursor`의 대기 글 목록과 수집 비밀은 이 화면에 주지 않는다. `POST /api/users`는 비밀번호 없는 행을 만들 수 있어 관리 화면은 부르지 않는다.
- `web/src/typed-router.d.ts`는 생성물이고 gitignore 대상이다. 없다고 만들지 않는다.
- CI는 Python을 검사하지 않는다. collector를 건드리면 `pnpm lint:py`·`typecheck:py`·`test:py`를 직접 돌려야 한다.
